## 3. 删除/收敛顺序（建议）

1. **C4 旧执行流：已删除**（2026-11-18，计划 2026-11-18-006 批次 2）。`ExecutionFlow` 组件、4 处渲染点、`messageExecutionFlow` / `visibleExecutionEvents` / `recentNarration` 数据链均已移除；`executionEvents` / `showExecutionFlow` / `executionFlow.events` 保留为 C1/C2 时间线数据源。下一步与系统提示改为 `.tl-next-step` / `.tl-system-notes` 常驻行。
2. **C5 结论卡**：v3 下已关闭且终稿已由 C2 承担；基线路径待产品确认后删。
3. **C6 `RunSummary`**：只在历史 `system` 消息与 Review 轮出现，等历史数据迁移后收敛。
4. **C3 基线折叠**：v3 开关已默认打开（ADR 0043，2026-11-19 复核）。2026-11-19-002 起 `transcriptV3` 常驻设置页「功能开关」可切换（ADR 0042），C3/C4/C5 基线通道在开关可关期间继续保留；基线通道与开关的删除时点 = 设置页移除该开关时一并处理。

> 目标终态：**C1 + C2（Work/Chat 运行轮）+ C7（无 runId 的纯问答/Review）+ C9（缺失提示）**。C4 已删除，当前 8 条，目标 4 条。

## 4. 变更本表的规矩

- 新增/删除任一通道，必须同时更新本表与《会话流前端规范》§2；
- 新增通道若与既有通道覆盖信息重叠，必须在表 §2 矩阵里显式写出重叠项，并在计划里说明收敛计划；
- 改动任一通道的渲染分支后，必须跑 `npm run test:ui-smoke`（打开有消息会话的运行时冒烟），见《运行时验收与门禁规范》。

## 5. 增补：图表工作台信息渲染决策（2026-11-19，计划 2026-11-19-001 / ADR 0041）

图表工作台（chart_*/board_*/data_* 工具、charts/&lt;slug&gt;/ 产物）**不新增 ChatPanel 渲染通道**：

| 信息 | 渲染位置 | 与既有通道的关系 |
|---|---|---|
| chart_* 工具调用过程 | C1/C2/C7 通用工具行（`runs.mjs` 中文动词 + 工具元数据图标） | 复用既有"工具调用"行，零新通道 |
| 导出产物（SVG 等交付文件） | ArtifactCard（产物卡，`charts/<slug>/exports/`；project/** 内部文件按 runs.mjs 判定排除） | 复用产物卡通道 |
| 图表内容本体 | App 级"图表工作台"标签（`kind=chartWorkbench`，非会话流通道）；agent 新建图表（chart_created 同会话）自动开标签 | 不在会话流内渲染，无重叠 |
| 数据表变更刷新 | 全局流 `chart_changed` → App 去抖 → 工作台标签内刷新 | 事件驱动刷新，不进会话流 |

矩阵检查结论：上述信息与 §2 矩阵各行零新增重叠（工具调用行、产物卡均为既有行）；缩略图预览卡若未来要进会话流，须按 §4 规矩先在此表补行再实施。
