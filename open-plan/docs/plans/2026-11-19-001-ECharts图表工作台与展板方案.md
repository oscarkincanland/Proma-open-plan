# ECharts 图表工作台与展板方案

> 状态：✅ 已确认（2026-11-19 用户批准 v2；拍板点 2/5/6/7 采用推荐项一并生效）　级别：S3（跨 client/server/契约/数据）　日期：2026-11-19　版本：v2（已确认）
> 版本记录：v1 初稿（2026-11-19）；v2 按用户拍板纳入「数据表编辑视图」（2026-11-19 拍板：形态=独立工作台+展板 / 表格范围=带数据表编辑 / 顺序=地基→单图→展板→上画布），范围实质变化已按 §7.3 重新审查。
> 依据：AGENTS.md §7.0 文档先行、§7.2 计划分级、§7.3 对抗审查；REQUIREMENTS.md R17（创作画布）、地图模块（R 地图系列）；ADR 0002/0003/0005/0025/0031/0033/0035。

## 0. 一句话方案（改前 → 改后）

- **改前**：ECharts 只能靠 `echarts-canvas-chart` 技能（007）服务端 SSR 渲染成**静态 SVG** 塞进画布，不可交互、不能在会话中持续调优、agent 没有一等公民的图表工具。
- **改后**：新增「图表工作台」一等公民模块——内置**数据表**（类多维表格的记录/字段编辑，用户与 agent 均可读写）+ ECharts 交互式图表（图表绑定数据表）+ **展板**（多图表仪表布局）；可在会话中引用并持续调优，可一键导出静态 SVG/PNG 上画布或交付。

## 1. 背景与动机

1. 2026-11-11 已通过技能方式落地 `.claude/skills/echarts-canvas-chart/`（计划 `2026-11-11-007`）：ECharts option → SSR 静态 SVG → `canvas_write` 作为 `svg` 元素上板。经验证：SVG 输出为纯几何、可过画布防脚本清洗；PPTX 导出时作为矢量图片嵌入。**边界**：静态、一次性、无会话闭环、无数据管理，agent 只能"盲写 option"再靠用户看效果。
2. 用户本次诉求（原话要点）：可直接用 ECharts 做图表；渲染在**画布或展板**上；能**加入会话**进行修改调优；**agent 可实时调用**；形态类比「agent 版多维表格」——即"结构化数据 + 视图 + agent 全链路操作"。
3. 画布对象模型（`server/创作画布.mjs` L88-96 `ELEMENT_TYPES = text/rect/line/image/svg/video`）不支持交互式对象，画布前端 SVG 用 `data:image/svg+xml` 的 `img` 承载（`client/src/components/创作画布.jsx` L195-320），**天然不支持交互脚本**。交互式图表不应硬塞进画布对象模型。

## 3. 产品形态对比

| 维度 | A. 画布新增 chart 元素类型 | B. 独立图表工作台（含展板） | C. 混合：B 为主 + 静态导出上画布 |
|---|---|---|---|
| 交互式图表（tooltip/legend/缩放） | ✗ 画布 SVG 管线是静态 img，需重写渲染分支且引入脚本安全面 | ✓ 原生交互 | ✓ 工作台内交互 |
| 与既有画布对象模型冲突 | 需扩 ELEMENT_TYPES、导出 PPTX/PDF 降级逻辑全动 | 无冲突 | 无冲突 |
| 展板（多图仪表） | 勉强（画布板可摆，但无网格布局语义） | ✓ 网格布局 | ✓ |
| 会话调优闭环 | 弱 | 强（引用+事件刷新） | 强 |
| 工程量 | 表面小实则侵入画布核心 | 新模块（对齐画布模式，路径清晰） | B + 一条导出链 |
| 违反"不重复造轮子"风险 | 低 | 中（需证明与画布不重叠：交互图表/数据视图是画布没有的能力） | 低 |
| 结论 | 不推荐 | 可选 | **推荐** |

**推荐 C**：交互调优在独立工作台完成；交付上板走"导出静态 SVG → 既有 `canvas_write` svg 元素"链路（已验证可行），画布继续负责 PPT/排版类交付，图表工作台负责数据可视化。

## 4. 推荐方案设计

### 4.1 落盘与数据模型（无数据库，对齐 ADR 0005）

```
charts/<slug>/project/          # 位于当前工作区根（对齐 AGENTS.md §6 产物必须写当前工作区）
  manifest.json          # 图表/数据表清单：[{id, kind:"chart"|"dataset", title, updatedAt}]（增量更新，避免全量重写放大）
  datasets/<datasetId>.json # 数据表：{ id, title, fields:[{name,type}], rows:[[...]], note? }
                         # type: number|string|date；行数/类型服务端校验；用户 UI 与 agent 均可读写
  chart-<id>.json        # { id, title, option(ECharts option JSON), data, note? }
                         # data: { kind:"dataset"|"inline"|"csv", datasetId?, inline?, csvPath?, expectRows? }
                         # dataset 绑定：渲染时把数据表行合并进 ECharts option.dataset.source；数据表变更联动刷新
  boards/<boardId>.json  # { id, title, layout:[{chartId, x, y, w, h}], theme? }
  assets/                # 渲染快照（会话卡缩略图）
  .history/              # 时间线（对齐画布 ADR 0034 精简版）
  .trash/                # 软删除回收（对齐 server/创作画布.mjs:71）
charts/<slug>/exports/   # 导出产物（SVG/PNG/展板 HTML）——slug 顶层（与画布同构），产物台账可见
```
（实施期修正：exports/ 从 project/ 内提到 slug 顶层，避免被"project/** 内部文件不进产物台账"规则误隐藏——方案 §4.1/§4.2 两处表述不一致，以本修正为准。）

- 校验：option 必须为合法 ECharts option JSON（服务端 schema 校验深度/尺寸限额对齐 `CANVAS_LIMITS` 思路）；**绑定 datasetId 的图表，series 不得直连 data，必须用 dataset/dimensions 形态**（服务端 chart_write 归一化或拒绝；两种形态并存时拒绝写入并给错误码——既有技能模板为 series.data 直连形态，templates/ 检索 dataset 零命中，直接合并不生效）；CSV 导入统一落成数据表（datasets/，note 记录来源路径，chart 仅绑 datasetId）；CSV 校验 `expectRows vs actualRows`，不一致产出 `data_integrity_failed`（对齐领域硬约束）；编码复用 gb18030 回退与 BOM 归一先例；数据表另校验 fields 与 rows 行宽一致、拒绝空表/空列、date 字段以 ISO 8601 存储解析。
- 限额（建议值，阶段 0 定案）：单数据表 ≤ 5000 行 × ≤ 64 列；单 option JSON ≤ 512 KB；展板单板 ≤ 24 图表。
- 生命周期：新增 `chart_delete`/`board_delete`/`data_delete`（destructive + forceConfirm，软删除进 `.trash/`）；`board.layout` 引用已删除/不存在图表、图表绑定已删除数据表时，渲染跳过并标记 `missing`，不阻塞整板。
- 数据表联动：图表经 `data.datasetId` 绑定数据表；数据表变更以 **datasetId 为事件粒度**（一次写入一条 `chart_changed`），前端按绑定关系扇出刷新，去抖窗口常量可注入（默认 ~200ms，测试注入 0）；用户编辑未保存（dirty）时收到远端变更→冲突提示（保留本地/采用远端），不静默覆盖。
- 演示数据：agent 用演示数据建图必须带 `note:"演示数据"` 标记并在卡片展示（沿用领域约束）。
- 产物台账：`charts/<slug>/project/**` 内部文件不进产物清单与会话结果卡（对齐 REQUIREMENTS.md L356-357 画布同款规则）；导出覆盖旧产物沿用 artifact_conflict 事件语义，不把整轮误降级为失败（L371）。

### 4.2 Agent 工具族（12 个：chart_* 5 + board_* 4 + data_* 3）

| 工具 | 职责 | 默认审批 |
|---|---|---|
| `chart_read` | 列图表/读单个图表 option+data | allow |
| `chart_write` | 创建或全量更新图表（slug+id+option+data） | allow |
| `chart_set_data` | 仅改数据（inline 或绑定 CSV） | allow |
| `chart_export` | 导出 SVG/PNG 到 `exports/`；产物进产物台账 | ask（对齐 canvas_export） |
| `board_read` / `board_write` | 展板读/全量写（布局 JSON） | read allow / write allow |
| `board_export` | 展板导出（PNG/HTML） | ask |
| `chart_delete` / `board_delete` | 软删除进 `.trash/` | ask + destructive + forceConfirm（对齐 canvas_delete） |
| `data_read` | 读数据表（列表/单表含字段与行） | allow |
| `data_write` | 全量写数据表（fields+rows，行数/类型校验）——agent 改记录的主通道 | allow |
| `data_delete` | 删除数据表（绑定图表标记 missing） | ask + destructive + forceConfirm |

- 上画布不新增工具：agent 用 `chart_export` 得到 SVG 文件后走既有 `canvas_write`（svg 元素）与 `canvas_import`。**不新增 chart_to_canvas 专用工具**，避免与画布写入审批双轨。
- 只在 Work 开放；Chat/Review 不持有（对齐 R17 与地图先例）；Chat 中历史图表可只读预览。
- 运行时开关：对齐 `creativeCanvas` 先例（server/task.mjs:63-65 默认关、server/index.mjs:6489 API 层拦截），新增 `chartWorkbench` flag 门控 chart_*/board_*/data_* 与工作台入口；默认值见拍板点 7。
- 同步接线：`server/task.mjs` 白名单与模式级裁剪、`server/审批策略.mjs` matchToolAction 规则（L144，canvas_* 先例 L90-92）、`planTaskCapabilities`、`server/runs.mjs` 显示名、`server/工具元数据.mjs` 元数据、`scripts/能力契约测试.mjs` L39 能力枚举、`test:capability-contract`；ask 类工具需确认既有审批弹窗组件支持（不新建审批 UI 结构）。
- 事件契约：`chart_changed` 按 canvas_changed 先例（事件注册表 L255-257）正式登记并发射，payload 带 slug/chartId/datasetId/missing；与 ADR 0033 收敛方向的张力通过"单一聚合事件 + 细分字段"化解（不拆 dataset_changed/board_changed 等细分名）。

### 4.3 事件与前端渲染

- 新事件：`chart_changed`（slug+chartId+datasetId+boardId 可选），按 ADR 0003 正式登记进 `server/事件注册表.mjs`（与 ADR 0033 的张力见 §4.2，由用户拍板）；数据表变更以 datasetId 驱动所有绑定图表/展板刷新（前端去抖合并）；刷新行为对齐画布板级增量刷新模式；会话绑定当前图表工作台 slug（对齐 mapProject 持久化先例）。
- 前端新组件：
  - `ChartRenderer.jsx`：echarts 封装（动态 `import("echarts/core")` 按需注册 Bar/Line/Pie/Scatter/Sankey + 必要组件；**双主题**注册 light/dark，token 对齐 `DESIGN.md`/`styles.css` 变量）。
  - `图表工作台.jsx`：单图编辑（左侧图表列表 + 中间渲染区 + 右侧 option/数据面板），对齐创作画布交互骨架与卡片化圆角风格。
  - `图表展板.jsx`：网格布局渲染 board JSON（拖拽调位可后置）。
  - `数据表面板.jsx`：记录/字段表格编辑视图（增删改行、列名/类型）。**既有 ExcelGrid.jsx 不满足**：其网格只承载单元格值（ExcelGrid.jsx:15）、按 A1 ref 写回 xlsx（:94），不支持增删行与 fields 结构编辑；其内部封装的 x-data-spreadsheet（ExcelGrid.jsx:2、package.json:33 ^1.1.9）同样无结构编辑。故新增本组件，仅**参考** ExcelGrid 的 dirty 追踪与保存交互；底层直接用 x-data-spreadsheet（已在依赖）或轻量自绘表格，阶段 0 验证后定案。
- 预览/标签：tab 类型经画布标签栏（tab.kind 扩展）登记；导出的 .svg/.png 文件预览复用既有文件格式能力矩阵，无需新登记。
- 会话流：新增"图表卡"渲染通道（缩略图 + 标题 + 打开工作台），**登记进《会话流渲染通道清单》**并检查与 ArtifactCard 的重叠矩阵；导出产物仍走 ArtifactCard。
- 调优闭环：工作台选中图表或数据表 → 复用 ADR 0035 结构化引用注入输入栏 → 用户说"把柱状图改成堆叠"/"第三行数值改成 42" → agent 调 `chart_write/chart_set_data/data_write` → `chart_changed` 事件驱动工作台刷新。

### 4.4 「agent 版多维表格」的范围收敛

类比映射（用户已拍板 2026-11-19）：**数据表（记录+字段，可编辑）↔ 多维表格的表；图表 ↔ 图表视图；展板 ↔ 仪表盘；agent 工具 ↔ 全链路读写自动化**。首版交付「数据表 + 图表视图 + 展板 + agent 读写」闭环。完整多维表格的**跨表关联、公式列、多视图（看板/日历/画廊）、字段级权限**不在本方案范围（列入不做清单，后续单独立项）。

## 7. 测试与门禁

- 单元：option/CSV/数据表校验、限额、导出；事件 payload schema 校验。
- 契约：`test:capability-contract`（白名单=能力计划=实际工具三方一致）。
- UI：`test:ui-smoke` 判据需扩展（现判据仅"开有消息会话+折叠"，见 `scripts/聊天界面冒烟检查.mjs` L10-15），增图表工作台开卡/编辑/导出路径后同步扩展断言，避免只断言字符串存在。
- 边界：非法/空 option 拒绝；series 直连 data 与 datasetId 绑定互斥；CSV gb18030/BOM 编码；数据表行数/行宽/类型/空表校验（expected vs actual）；删图/删数据表后展板与图表 missing 降级；导出覆盖触发 artifact_conflict 不误降级；联动刷新测试以可注入去抖窗口做确定性断言（事件→扇出→单次渲染）。
- 性能：echarts 动态 import 分包，不进主包；`test:perf-budget` 若命中已知失败基线需给签名证明未新增失败。
- 回归：画布 SVG 上板与 PPTX 导出既有测试不转红。
- 文档同步：PRD（R 编号）、DESIGN.md（新组件与交互规范）、会话流渲染通道清单、变更日志。

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| echarts 体积拖累主包/首屏 | 仅动态 import + 按需注册；perf-budget 门禁卡口 |
| option 由 LLM 生成，合法性不稳定 | 服务端 schema 校验 + 明确错误码；模板兜底（复用技能模板） |
| 与画布职责模糊 | 硬边界：交互调优只在工作台；画布只收静态 SVG；文档写清分工 |
| 双主题错位 | theme 对象从 styles.css 变量取色；ui-smoke 加暗色断言 |
| CSV 大文件 | 限额（对齐 CANVAS_LIMITS 思路）+ 校验失败即断 |
| 事件串页 | 沿用会话/标签过滤现状，事件带 slug 由前端比对当前绑定再刷新 |
| 工作区切换后 slug 绑定失效 | 会话绑定持久化 + 目录缺失标记与防护（复用工作区切换既有防护逻辑），缺目录时只读提示不崩溃 |
| 数据表高频编辑与图表刷新竞态 | 事件去抖合并 + 渲染按 chartId 幂等；agent 批量改数走 data_write 一次性落盘 |
| 大数据表编辑卡顿 | 行数限额（对齐 CANVAS_LIMITS 思路）+ 分页/虚拟滚动（复用 ExcelGrid 既有能力） |
