## 3. 修改原则（逐套件先甄别再动手）

1. **默认改测试基线**：失败源于守护测试期望未跟上有意的新增/变更 → 更新期望值/清单/计数，提交说明写明依据（对应功能或需求编号）。
2. **改产品代码仅当**：甄别发现行为违反 PRD/DESIGN/AGENTS 约束 → 修产品 + 同步文档 + 加回归测试；此类改动先向用户确认（本计划 D1/D2）。
3. **棘轮类守卫**（硬编码色值/动画计数冻结）：优先把新增硬编码值收敛进设计令牌；确属合理新增的才放宽棘轮计数并注释原因。涉及视觉语义的收敛需同步 DESIGN 并确认。
4. 每套件修复后立即直跑复绿，不留半成品。
