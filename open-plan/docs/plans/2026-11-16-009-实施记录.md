## 7. 启动即崩修复（用户实测回归，2026-11-17）

- **现象**：用户解压便携版到 `D:\guiju桌面端\` 双击 → 弹「A JavaScript error occurred in the main process」ERR_REQUIRE_ESM（`main.cjs:22` require `./浏览器视图.mjs`）。
- **根因**：`浏览器视图.mjs` **内容是 CJS**（require/module.exports）但扩展名是 `.mjs`；Electron 33 内置 Node 20 无 `require(esm)`，主进程顶层 require 直接崩。该文件由 `6949ed4e`（内置浏览器）晚于 v0.13.25 包引入，且本环境沙箱无法启动 Electron GUI——产物冒烟（只起服务）与契约测试（源码式）双防线都没覆盖主进程启动链路。
- **修复**：`浏览器视图.mjs` → `浏览器视图.cjs`（内容本就是 CJS，零代码改动）；`main.cjs` 引用路径同步；README 更新。
- **防再犯**：`scripts/桌面端契约测试.mjs` 新增静态契约「壳文件扩展名与模块格式一致」——desktop/src 禁止 `.mjs`、禁止 require `.mjs`、禁止顶层 ESM import。
- **产物**：按修复后树重打（--repack + NSIS + smoke 39/39 + 便携 ZIP），并**把 `v0.13.26` tag 移动到修复提交**（tag 未 push，发布语义 = 可启动的安装包）。
- **遗留**：主进程启动仍无法在本环境自动化实测（沙箱拦 GUI）——用户在 `D:\guiju桌面端\` 重新解压/覆盖后双击 `GuiJu.exe` 验证窗口出现即闭环。
