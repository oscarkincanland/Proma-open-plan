## 1. 定位结果（含 v1 纠错）

### 1.1 建议①「硬拦改软提醒」

| 机制 | 位置（复核后） | 实际行为 |
|---|---|---|
| 回合/工具/时长预算 | `server/运行预算.mjs:16-21`；`server/运行开关.mjs:129` | **默认不生效**：`runBudgetUnlimited` 默认 `true`，`运行预算.mjs:178-186` 直接跳过硬预算 |
| 重复无进展 | `运行预算.mjs:23`（常量）、`:206/:209`（判定） | 返回 `level:"soft"`；`工作台把关.mjs:48-52` 对 soft 放行 |
| 同一操作连续失败 | `运行预算.mjs:25`、`:194-196` | `level:"hard"` → `工作台把关.mjs:53-55` block。**运行预算范围内唯一默认生效的硬闸** |
| 同参提醒 | `agent.mjs:569/651/661-663` | 第 3 次同参 → `tool_repeat_warning` + `steer`，不拦 |
| 回合级硬停 | `agent.mjs:6468/6474` | 仅 `unlimited=false`（`运行预算.mjs:243` unlimited 返回 null） |

**纠错（v1 说错的两点）**：
- ❌ "重复 2 次就硬拦" —— 错。`REPEAT_LIMIT=2` 是 **soft**，第 3 次才 soft 提醒。
- ❌ "参数已经变了还会被拦" —— 错。指纹 `previous.key === key`（`:194`）含参数，参数变即不触发；且只保留最近一次（`:225-232`），不存在"永久拦死"。
- ✅ 真实风险只剩一条：**同一操作连续 2 次同类失败即 hard block**，而失败原因可能是网络/占用（**不同错误被当成同一失败**）。

### 1.2 建议②「目标空闲续轮」——无自动驱动，且**不能复用恢复通道**

| 事实 | 位置 |
|---|---|
| goal 字段（`status/maxTurns/turns/usedTokens/activeMs/lastRunId`） | `goal.mjs:43-61`（normalize）、`:113-128`（setGoal） |

| **可续集合不含 completed** | `index.mjs:5528` `CONTINUABLE_RUN_STATUSES = recovered/failed/cancelled/aborted`；`runs.mjs:1924 canResume` 同 |
| 目标事件 | `事件注册表.mjs:209-211` |
| 静默回收 180s→cancelled | `index.mjs:7775`、`:7813-7819`；启动标 recovering `:7670` |

**关键结论（审查 M1）**：正常"目标没做完"的场景上一轮是 **completed**，`startContinuation` 会直接 throw。所以 P2 必须**两条路径**：恢复用 `startContinuation`，目标推进用 `beginRun + promptWithContext`。

### P2（S3）目标空闲推进（两条路径）

**路径 A 恢复**（沿用）：`startContinuation(sourceRun,'resume')`，仅 `failed/cancelled/aborted/recovering` —— 且**用户主动取消**（`cancelRequested`）与**重启 recovering** 不自动继续（审查 M3）。

**路径 B 目标推进**（新增，主路径）：上一轮 `completed` 但目标未达成时：

1. **构造**（与 `startContinuation` 同配方，`index.mjs:5639-5668`）：`createTaskEnvelope({...老任务, id:undefined, goal:目标文本, text:目标文本, threadId, references, workflowId, recoveryOf:null, recoveryAction:null, constraints:[...]})` → `planTaskCapabilities({text, task, references})` → `requireWorkspaceWriteForTask(...)` → 按需 officecli 预检；
2. **建 Run**：`beginRun({ clientId, threadId, sessionId, cwd, task, references, workflow, projectId, capabilityPlan, runtimeSnapshot })`；
3. **执行包装**（`executeGoalRound`，镜像 `executeContinuation` `index.mjs:5555-5570` 的收尾链）：`snapshotWorkspace` → `promptWithContext(key, 目标 + 上轮终稿摘要 + 已完成/未完成清单)` → `waitForFlush` → `validatableRunArtifacts` → `finishRun`（含 `run_finished` 广播）。**缺这段，新 Run 永不进终态，180s 后会被回收器判 cancelled 并与自动推进互相拉扯**（审查 R2）；
4. **不写** `recoveryOf/recoveryAction`（避免"继续自 Run X"语义错位，审查 M1）。

**取消语义（审查 R3 更正）**：
- 判"用户取消"读 Run 上的**持久字段** `run.cancelRequestedAt`（+ `status === "cancel_requested"`），不用内存态 `cancelRequested`（会被回收器复位，`index.mjs:7739/7822`）；
- **任何来源的 `cancelled` 都不自动继续**（用户取消、回收器静默收尾、取消看门狗），避免"点停止后 30 秒自己又跑起来"；
- 路径 A 只服务 `failed` / `aborted` / `recovering`，且 `recovering` 需在进程启动 **N=10 分钟**后（审查 M3）。

**调度**（新增 `server/目标续轮.mjs`）：
- 触发：`OAW_GOAL_AUTO_CONTINUE`（**默认关**）、`goal.status==="active"`、`turns < maxTurns`（0=不限，受 `OAW_GOAL_MAX_ROUNDS` 默认 10 硬顶，**达顶必须写 `status:"max_turns"`**，审查建议 5）、`usedTokens < budgetTokens`（0=不限，注意 `usedTokens` 仅在 Run 结束时更新，`goal.mjs:237-263`，**不能指望轮内强停**，审查建议 6）；
- 空闲判定**复用**：`agent.mjs:1209-1224 listSessionStates()`（busy/compacting/queuedCount/chainDepth/activeRunId）、`审批策略.mjs:274 pendingApprovals`、`agent.mjs:1173 pendingAsks`；
- **"上一个 Run"用 `runs.mjs:1958 listRunSummaries()`**（读 `runIndex` 元数据，已含 `status/sessionId/lastEventAt/updatedAt`），给它加可选 `sessionId` 过滤即可；**不要**用 `listRunStallCandidates`（它只收 running/queued/recovering，`runs.mjs:583/596`，答不了"上轮 completed"——审查 R1），也**禁止**构造完整 Run 列表（`index.mjs:7791-7792` 有 1976ms 前车之鉴）；
- 目标枚举：在 `goal.mjs` 增 `listGoals()`（读 `.oaw/goals/`，**不新建第二事实源**）；
- 防重入 + 退避：`roundRunning` 门闸；`startContinuation`/`beginRun` 抛错（如预检失败 `index.mjs:5620-5633`）→ 指数退避（60s→300s），连续 3 次失败停自动；
- 无进展：连续 2 轮「产物数 / 变更数 / completion.status」都没变 → `status:"blocked"` + `goal_auto_blocked`；
- 用户插话优先：轮次进行中收到用户消息 → 取消本轮自动续（不抢用户）。

**事件**（必须登记，`事件注册表.mjs`）：`goal_round_started`、`goal_round_skipped`、`goal_auto_blocked`。是否标 `runEvent` 需同步 `scripts/事件注册表测试.mjs:89-100` 的基线（审查 M8）。
