## 2. 关键实现决策（实施期修订，均已回写方案/ADR）

1. **exports/ 提到 slug 顶层**：初版落在 `project/` 内，会被 `isChartInternalArtifactPath`（project/** 不进产物台账）误隐藏；改为 `charts/<slug>/exports/`（与 `designs/<slug>/exports/` 同构），方案 §4.1 布局已修正留痕。
2. **服务端承担 SSR 导出**：ADR 0041 初稿写"服务端不做 ECharts 渲染"，实施按更优路径修正——agent 工具运行在服务端，前端无法参与；采用技能 007 已验证的 SSR 方案，echarts 同时进入 root（server）依赖。ADR §2.2 已改写。
3. **`OAW_CHART_WORKBENCH` 默认开**：方案拍板点 7 原推荐"默认关"依据（creativeCanvas 默认关的注释）已过时——当日合并的 ADR 0043 明确新功能开关全部默认打开。按 ADR 0043 默认开、显式 0 回退，ADR §2.7 留痕。
4. **SVGRenderer/CanvasRenderer 必须显式注册**：echarts/core 按需注册不含渲染器，SSR 用 `SVGRenderer`、前端用 `CanvasRenderer`（首次运行才暴露，已入测试）。
5. **产物台账排除**：`runs.mjs` 新增 `isChartInternalArtifactPath`（charts/<slug>/project/** 与 operations.jsonl），接入四处产物过滤——导出文件（exports/）保持可见。

## 4. 已知边界与归因（非本改动引入）

- `test:harness-flags` 失败：toolMetadata 默认值翻转来自在途 ADR 0043 合并改动（git diff 证明非本改动文件行）。
- `test:perf-budget` 失败：CSS 722.2KB > 720KB，+8KB 为远端合并带入的 `.markdown-body/.md-doc-*` 已提交规则（styles.css 未被本改动触碰；旧 dist 批次早于该合并），建议合并工作流上调预算基线。
