## 1. 现象（用户原话）

> 「画布 agent 在操作的时候，容易有 bug，比如出现了画布理解上的出入？可能是地图画布、可能是创作画布，第二画布在编辑的时候，画布容易都叠加在一起？」

两个独立缺陷：

- **A. 理解出入**：agent 不知道该改哪张画布，或把「地图项目」与「创作画布」混为一谈。
- **B. 多板叠加**：新建的第二块板压在已有板上，物理重叠。

## 2. 根因（全部有代码位置证据）

### A1 创作画布没有「当前画布」上下文（地图有）

| 侧 | 机制 | 位置 |
|---|---|---|
| 地图 | `mapProject` 进任务信封 → 摘要 | `server/task.mjs` `createTaskEnvelope` / `taskSummary` |
| 创作画布（改前） | 只有会话 header 存 slug，**不进任务信封** | `server/index.mjs` `/api/sessions/:id/canvas-context` |

结论：agent 每轮只能 `canvas_read` 列全部画布、靠标题猜 slug。

### A2 slug 有两套推导规则（重复造轮子）

- `server/agent.mjs` 内联 `canvasSlugify`：`toLowerCase()` + 只留 `[\p{L}\p{N}_-]`
- `server/创作画布.mjs` `slugifyTitle`：保大小写 + 只折叠标点

实测差异：

| 标题 | agent 侧 | server 侧 | 一致 |
|---|---|---|---|
| Open Plan（规聚）项目介绍 | `open-plan-规聚-项目介绍` | `Open-Plan-规聚-项目介绍` | ✗ |
| Q1 汇报_v2 | `q1-汇报_v2` | `Q1-汇报_v2` | ✗ |
| 规聚 10分钟汇报 | `规聚-10分钟汇报` | `规聚-10分钟汇报` | ✓ |

后果：同一标题推出两个 slug → 生成两张「幽灵画布」；agent 写到自己拼的那张上，用户在另一张里看不到变化。

`chart_write` 同款（`chartSlugify` vs `slugifyWorkbench`）。

### A3 术语把两件事说成一个词

`client/src/App.jsx` 注释把 `project_created`（地图**项目**）写成「新建**地图画布**」；`DESIGN.md` §8.4 另有「地图模式画布联动」小节。「地图画布」是可指两物的空词。

### B1 `add_board` 缺省 layout 恒为 (0,0)（主因）

```js
// 改前 server/agent.mjs
const layout = parse(params.layout, { x: 0, y: 0, w: 1280, h: 720 });
```

而自动下移只在 `layout.y` **不是有限数**时才生效（`server/创作画布.mjs` `writeBoard` 的 `maxBottom + 120` 分支）。agent 传了 `0`，于是每块新板都落在 (0,0)。

UI 创建不传 layout，才走自动下移——这正是「agent 建板必叠加、手动建板不叠加」的确定性来源。

**真实产物证据**：`office-workspace/designs/od-linkage-test/project/canvas.json` 中 `boards/cover.board.json` 与 `boards/od-overview.board.json` 同为 `x=0, y=0, w=1280, h=720`。

### B2 标签 id 跨工作区撞车

`client/src/画布状态.js` 的 `designTabId` / `chartTabId` 各自内联「只取 workspace 末两段」算法：

```
D:\前端\a\project  -> design:a-project:汇报
E:\后端\a\project  -> design:a-project:汇报   ← 相同
```

撞 id 后两个 `.app-canvas-body` 互相顶替。

### B3 隐藏画布仍抢键盘

地图模块遮罩用 `visibility: hidden`（`client/src/styles.css` 的 `.app.map-module-active > .app-canvas-slot`），元素**仍在布局里**，`offsetParent` 不为 null。创作画布的快捷键守卫只判 `offsetParent === null`，于是被遮住的画布照样响应 Space / H / Delete / Ctrl+Z —— 地图与创作画布互相串台。

## 4. 复用清单

- **复用**：`画布/画布模型.js` 的 `workspaceKey`、`designTabId`（唯一实现即模型层）；`server/创作画布.mjs` 的 `slugifyTitle` 与「最下方板底 + 120」既有落位口径（`BOARD_GAP_Y` 取其 120）；`server/图表工作台.mjs` 的 `slugifyWorkbench`；`a2762565` 已落地的 `creativeCanvas` 信封链路（信封 → 摘要 → `App.boundCanvasSlug` → `ChatPanel`）作为同构模板，本次只补测试；`askConfirm`/既有 Feedback 不动。
- **新增**：`placeWithoutOverlap`、`rectsOverlap`、`BOARD_GAP_Y`、`画布可见`、`CANVAS_SLUG_REQUIRED` 错误码。
- **与既有「整理画板」的分工**（对抗审查 M7）：`创作画布.jsx` 的「整理画板」是**网格重排**（3 列 + 板距 + 写回 canvas.json），面向用户主动整理；`placeWithoutOverlap` 是**单板落位避让**，面向新建板时不叠上去。目的不同、不改同一份状态，不构成等价实现。
- **不新增**：不新增组件、不新增事件、不新增 REST 路由、不新增依赖、不新增开关。

## 5. 明确不做

- 不改地图侧的任何行为（只改注释措辞）。
- 不给 `mapPreview` 单例标签改成多实例（`SINGLETON_TAB_KINDS` 语义保留；另立计划）。
- 不做既有画布数据的自动迁移/去重叠（只保证新板不叠；`od-linkage-test` 那两张旧板留给用户手动「按板间距整理画板」）。
- 不改 `localStorage` 标签 id 的历史值（旧 id 不再命中后按「未保存过」处理，自然重建）。
  **实测更正**：标签数据**不会丢**——`loadCanvasState` → `sanitizeTab` 对 `kind=design` 会按 `tab.payload.workspace + slug` 调用 `createDesignTab` **重新推导 id**，所以旧条目仍能恢复成新 id 的标签；唯一影响是保存的 `activeId` 不再命中，`loadCanvasState` 回退为「激活最后一个标签」。无需迁移。
- 不把 `offsetParent` 判据整体删掉（仅在 `checkVisibility` 不可用时作为兜底）。
