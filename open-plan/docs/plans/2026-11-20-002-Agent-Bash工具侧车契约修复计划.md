## 0. 结论

**不是 bash/npm 不存在，而是默认切到“内核侧车”执行后契约断裂。** Pi SDK 的 `BashOperations.exec` 要求 `onData(Buffer)` 回放输出、返回 `{ exitCode }`；侧车既不回放也不返回 `exitCode`，于是所有 bash（含 `npm`）结果都是 `(no output)` + `Command exited with code undefined`。

**v2 修订（采纳对抗审查）**：不再由侧车重写 spawn/超时/取消/进程树语义，而是**复用 `agent.mjs` 已存在的 `createLocalBashOperations`**；侧车只保留并发门、统计与 `onData` 字节计数。这样 timeout（SDK 契约单位为**秒**）、abort（抛 `aborted`）、进程树终止、cwd/env 等全部与本地执行一致。

## 1. 现象与证据

### 1.1 实际 Run（`.oaw/runs`）

多个已完成 Run 的 `tool_end` 中 `bash` 均为：

```json
{"name":"bash","isError":true,
 "result":"{\"content\":[{\"type\":\"text\",\"text\":\"(no output)\\n\\nCommand exited with code undefined\"}], \"structuredContent\":{\"output\":\"\",\"truncated\":false,...}}"}
```

涉及 `run_80676f87…`、`run_6e417115…`、`run_9f8a0fad…`（3 次全失败）、`run_11f285c6…` 等。

### 1.2 时间线与触发

- 2026-11-18 的 4 个 Run 共 **59 次** bash 全部成功（带 `exit_code`）；
- 2026-11-19 08:57 起至 2026-11-20 02:16 的 7 个 Run 共 **18 次** bash 全部 `undefined`；
- 与未提交的 ADR 0043 默认翻转时间线吻合：HEAD `piBashSidecar: readFlag("OAW_PI_SIDECAR")`（默认关）→ 工作区 `readFlagDefault(..., true)`；运行中服务 `/api/status.runtimeFlags.piBashSidecar = true`。

### 1.3 契约对照（本机实测）

```text
SDK 本地执行：   local ops result {"exitCode":0}      onData chunks 1（"hi"）
当前侧车：       sidecar result {"code":0,"stdout":"hi\n"...}   onData chunks 0
```

Pi SDK `dist/core/tools/bash.d.ts`：

```ts
exec(command, cwd, options: { onData: (data: Buffer) => void; signal?; timeout?; env? })
  => Promise<{ exitCode: number | null }>
```

**补充实测**（对抗审查）：SDK 本地 ops 的 `timeout` 单位是**秒**（默认无超时）；超时抛 `timeout:<秒>`、取消（含 pre-abort）抛 `aborted`；超时需杀**进程树**且不能等 stdout 管道关闭。这些语义侧车目前全部未实现。

## 2. 用户可见变化（改前 → 改后）

- 改前：Agent 调用 bash/`npm`/`node`/`npx` 时只显示“执行失败/(no output)”，看不到输出与退出码。
- 改后：bash 行恢复输出 stdout/stderr 与真实退出码；`npm --version`、`npm run build` 等可用；超时/取消/进程树行为与本地执行一致；后台 bash 恢复（见 §5 决策 2）。
- 界面布局、工具名、审批规则、工作区边界不变。

## 6. 实施步骤

### P1 `server/内核侧车.mjs`：改为门 + 统计，委托执行器

新增/替换为：

```js
export function createSidecarBashOperations(manager, executor) {
  return { exec: (command, cwd, options = {}) => manager.run(command, cwd, options, executor) };
}

class BashSidecarManager {
  async run(command, cwd, options = {}, executor) {
    // 1) 并发门：满 4 时排队；排队中 abort → 移除等待者并抛 new Error("aborted")
    // 2) 入口先判 options.signal?.aborted → 抛 new Error("aborted")
    // 3) 包装 onData：只统计字节数（不缓冲），Buffer 原样透传
    // 4) try { return await executor(command, cwd, options); }
    //    finally { 释放槽位；记录耗时/stats；移除 abort 监听 }
    // 5) 错误分类：/timeout/ → timeout++；/aborted/ → aborted++；其它 failed++
  }
}
```

- **超时/取消/进程树/cwd/env/空命令/错误文案一律交给 `executor`（即 `localBash.exec`）**；侧车不设默认超时（SDK 契约无默认；120s 是 `normalizeBashOptions` 的应用策略）。
- 删除旧的 `execute` 直接 spawn 实现（或保留为 private，不再被生产调用）；同步更新 `scripts/优化项综合验收.mjs` 的 U5 旧 `{code}` 断言（见 P3）。

### P2 `server/agent.mjs`：注入 localBash 并透传选项

```js
const localBash = createLocalBashOperations(bashShell ? { shellPath: bashShell } : {});
const sidecarBash = createSidecarBashOperations(getBashSidecar(), localBash.exec.bind(localBash));

// runBash：
const runBash = async () => RUNTIME_FLAGS.piBashSidecar
  ? await sidecarBash.exec(effectiveCommand, cwd || ctx.workspace, execOptions)
  : await localBash.exec(effectiveCommand, cwd, execOptions);

// 后台任务：去掉 !piBashSidecar 互斥（决策 2 通过时）
const backgroundEnabled = RUNTIME_FLAGS.backgroundJobs;
```

审批、只读判断、写锁、staging 物化、job 创建/取消逻辑不变；`execOptions`（`onData/signal/timeout/env`）原样透传。

### P4 新增 `scripts/内核侧车契约测试.mjs`（`test:sidecar-contract`）

必须覆盖（每条用例都要能在修复前失败）：

1. **SDK 工具端到端**：`createBashToolDefinition(cwd, { operations: sidecarBash, exposeSessionEnvironment: false }).execute("tc1", { command: "echo hi" })` → `content[0].text` 含 `hi`、无 `(no output)`、`structuredContent.exit_code === 0`；
2. **真实命令**：`npm --version`、`node --version` 经同一适配器返回版本号（不调模型）；
3. **非零退出 + stderr**：`exit 3` 返回 `exit_code === 3`，输出含 stderr 文案；
4. **timeout 单位=秒**：`timeout: 1` + `sleep 2` → rejects `/timeout:1/`，耗时 ≈1s（不得是 120ms 或 120s）；
5. **abort**：pre-aborted 与运行中 abort 均 rejects `/aborted/`；排队中 abort 能出队且槽位不泄漏；
6. **并发门**：6 条并发，`snapshot().active` 峰值 ≤4；
7. **空命令/坏 cwd/ spawn error**：返回可解释错误（由 localBash 负责），`active === 0`；
8. **bg-job 条件静态断言**：`agent.mjs` 中 `backgroundEnabled` 不再带 `!piBashSidecar`（决策 2 通过时）。
