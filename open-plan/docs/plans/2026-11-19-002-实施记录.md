## 2. 实施期修正（相对方案）

1. **设置面/端到端选择器**：方案假设设置面为弹窗，实测为**模块视图**（`activeModule === "settings"` → `.module-view`）；E2E 锚点改为 `.module-view` + `.module-back` 返回按钮；护栏确认框为**应用内 ConfirmDialog**（`[aria-label="确认操作"]`，FeedbackHost 常驻挂载），非原生 confirm——E2E 已按实际 DOM 落地。
2. **`flagSource()` 入参语义**：入参为环境变量名（内部 `envToFlagKey` 转换），来源快照 `runtimeFlagSourcesSnapshot()` 才是语义名键——热更测试初版误用语义名调用已修正；API 的 `sources` 字段对 UI 输出语义名键。
3. **写盘失败注入方式**：Windows chmod 不阻断写入、「目录路径」场景被 `renameSync` 静默处理，故服务端加**配置路径类型守卫**（存在且非文件 → 直接失败），测试用「父路径为文件」注入（跨平台可靠）。
4. **判据 7 的加载期求值验证范围**：E2E 重启实例断言 flags 持久化与 UI 状态；「cadAgent 关 → 白名单无 cad_edit」的加载期求值断言由 `运行开关热更测试.mjs` ④ 在函数层覆盖（`/api/runtime-flags` 未暴露工具白名单端点，避免为此新增公开面）。
5. **ui-smoke 扩展范围**：env 锁定态/restartRequired 徽标断言不进 ui-smoke（它跑在用户真实实例上、环境不确定），由 `test:flags-e2e`（隔离实例）确定性覆盖；ui-smoke 只保留「分区渲染无错误」的冒烟断言。

## 4. 既有失败归因（§7.1-3）

- `test:cad`（CAD解析测试）：①「cadPreview 默认开 / cadAgent 默认关」断言 `cadAgent: readFlag(...)`——ADR 0043 批次把 cadAgent 改为 `readFlagDefault(..., true)` 后未同步该测试，**先于本批存在**；②「cadAgent 关：子进程反例」`true !== false`——同为 ADR 0043 批次遗留。本批仅按函数化新形态更新「文件树白名单」一条断言，未新增失败。
- `test:event-payload` / `test:event-emission`：变更日志既有记录（OAW_EVENT_SCHEMA_CHECK 默认改开、chart_exported 发射路径），与本批无关。
