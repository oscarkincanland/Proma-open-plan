## 1. 背景与目标

当前约 90 个运行开关收口在 `server/运行开关.mjs`（唯一事实源），但用户没有任何界面化修改入口：

- 取值优先级：环境变量 > `.oaw/runtime-flags.json` > 代码默认值（`server/运行开关.mjs:10`）；
- 快照在**服务启动时解析一次**，进程内不热更（`server/运行开关.mjs:125`），经 `/api/status` 只读下发（`server/index.mjs:383`、`server/index.mjs:402`）；
- 修改开关只能设环境变量或手编 `.oaw/runtime-flags.json`，且必须重启服务才生效。

用户本轮拍板三项诉求：

1. **生效方式：设置界面引入热更**——在设置页改开关，保存后即时生效（不重启服务）；
2. **暴露可感知的功能开关**——不是 90 个全上，只暴露用户可感知的功能开关；
3. **解决来源冲突的提示**——环境变量优先级高于配置文件，UI 必须明确提示「哪个开关被环境变量接管、设置页改了不生效」。

## 3. 方案四件事（§7.2 口径）

### 3.1 界面与操作怎么变（用户视角）

- **改前**：开关只能改环境变量或手编 `.oaw/runtime-flags.json`，改完重启服务；没有 UI。
- **改后**：设置面板新增「功能开关」分区（导航分组，常用开关默认展开、高级开关折叠）。每个开关一行：名称 + 一句话说明 + 来源徽标（默认 / 配置文件 / 环境变量）+ Toggle。**保存即 POST，立即生效，无需重启**；被环境变量接管的开关显示锁定徽标「环境变量接管，修改不生效」且不可切换；关闭护栏类/族总开关时弹应用内确认（askConfirm）。其他标签页经 `runtime_flags_changed` 事件同步刷新。

### 3.2 复用清单（复用 X，新增 Y，不新增 Z）

- **复用**：`server/运行开关.mjs` 全部解析/优先级/来源诊断逻辑（`readFlagDefault`/`flagSource`/`RUNTIME_FLAGS_FILE`）；`/api/status` 快照形态与 `client/src/运行开关.js` 消费端；`appendEvent` 广播通道与事件注册表；SettingsPanel 现有导航/分区/toggle 行样式与 `askConfirm`/`notifyError`（`client/src/components/Feedback.jsx`）；api.js 既有设置类 API 模式（仿 `mapSettings`/`mapSettingsSave`）；既有守护测试脚本模式（`scripts/GIS开关默认体验测试.mjs`）。
- **新增**：`server/运行开关.mjs` 内 `buildRuntimeFlags()`/`reloadRuntimeFlags()`/`runtimeFlagSourcesSnapshot()` 三个导出；`GET/POST /api/runtime-flags` 两个路由；事件 `runtime_flags_changed`；前端 `applyRuntimeFlagsSnapshot`/版本订阅 hook；api.js 两个函数；SettingsPanel 一个分区组件；三份新测试脚本（热更单测、API 契约、**开关设置端到端**）+ package.json 一条 `test:flags-e2e`。
- **不新增**：第二个开关解析管道、新的持久化格式（仍用 `runtime-flags.json`）、新的 SSE 通道（走既有事件流）、独立的开关清单文件（白名单定义在 `运行开关.mjs` 内）。

### 3.3 这次明确不做什么（不做清单）

1. 数值调参不进设置页：全部 `readPositiveInt` 项（心跳间隔、看门狗阈值、超时、字节上限、队列上限）与 `browserUrlAllowlist` 域名白名单继续走环境变量。
2. `feedbackV2` 不暴露、不改默认关（2026-10-28-006 D2 既有决策；应用内反馈已不依赖该开关）。
3. Qoder/Harness/BrowserAtomic 三族**族内单项**不逐项暴露（受 `|| 族总开关` 的 OR 语义支配，单项无独立生效意义），只暴露族总开关。
4. 不做多用户并发写冲突解决（单机单用户；写入用临时文件 + rename 原子替换，last-write-wins）。
5. 不做前端逐组件细粒度重渲染优化：版本号 bump 驱动顶层重渲染，`flag()` 内联读取自然生效；mount 期一次性接线只重接已知的两处（见 §6 阶段3），不穷举。
6. 不改审批策略语义、不把审批开关（permission）迁进功能开关分区（它已有「审批与权限」分区）。
7. 不做开关变更审计落盘（本轮只广播事件；审计需求出现时另立项）。

## 4. 总体设计

### 4.1 服务端热更管道（`server/运行开关.mjs`）

```js
// 现状：模块顶层一次性求值
export const RUNTIME_FLAGS = Object.freeze({ ...约90项... });

// 改为：求值逻辑收进 build 函数，绑定改 let（ESM live binding 对外可见）
function buildRuntimeFlags() { return Object.freeze({ ...同样的约90项求值... }); }
let RUNTIME_FLAGS = buildRuntimeFlags();

// 热更入口：重置持久化 memo + 重建快照
export function reloadRuntimeFlags() {
  persistedFlags = {};            // 重置 loadPersistedFlags 的单次缓存
  persistedFlagsLoaded = false;
  RUNTIME_FLAGS = buildRuntimeFlags();   // env 每次重读（进程内 env 不变，file 生效）
  return RUNTIME_FLAGS;
}
export function runtimeFlagSourcesSnapshot() { /* flagSources Map 的只读导出 */ }
```

- `flagSource()`/`noteSource` 机制原样复用，重建时来源随之刷新。
- `officeGateActiveFor`/`readOffFlag` 走 `readFlagDefault`（每次调用现读），memo 重置后自动吃新文件值，无需改。
- 语义不变：env 仍最高优先；`buildRuntimeFlags` 内部逐项逻辑与现状逐字一致（仅搬运）。

### 4.2 加载期求值点函数化（热可达性修复）

- `server/task.mjs`：`READ_ONLY_TOOLS`/`OFFICE_TOOLS`/`REVIEW_TOOLS`/`AGENT_TOOLS` 从模块级 frozen 常量改为**函数**（如 `agentTools()`），内部逻辑逐字保留（含注释），调用点同步；`test:capability-contract` 改为调用函数断言集合内容不变（集合成员逐字不变，仅求值时机从加载期变为调用期——每任务创建时求值一次，本轮任务内快照固定）。
- `server/workspace.mjs:49`：`CAD_EXT_SEGMENT` 常量改为函数 `cadExtSegment()`。
- `server/context.mjs:15`：模块级 `SUPPORTED` Set 改为函数 `supportedDocumentExts()`（每次调用现读快照，cadAgent 热更即时生效）。
- `server/index.mjs:6279`：**不改**。数据适配器注册是模块级动态 import，无法在运行中干净卸载（已注册的适配器在 flag 关闭后仍可见）；按拍板点5-A 处理——白名单中为 `dataAdapters` 标注 `restartRequired: true`，UI 允许切换但显示「重启后生效」徽标。

### 4.3 API 契约（新增，公开 API 变更按 §4.3 须用户确认——即本方案确认）

```
GET /api/runtime-flags
→ {
    flags: { ...runtimeFlagsSnapshot() },          // 生效值快照
    sources: { creativeCanvas: "default"|"file"|"env", ... },  // runtimeFlagSourcesSnapshot()
    editable: [ ...USER_EDITABLE_FLAGS 白名单 ],     // 设置页可渲染项；dataAdapters 附 restartRequired: true
  }

POST /api/runtime-flags        body: { flags: { <语义名>: boolean, ... } }
→ 校验：键必须在 USER_EDITABLE_FLAGS 白名单内，值必须 boolean；违规 → 400 { error }
→ 对 source === "env" 的键：跳过写盘（env 优先语义不变），响应中标注 envLocked: [键列表]
→ 其余键 merge 进 .oaw/runtime-flags.json（保留文件中其它未知键；临时文件 + rename 原子写）
→ 写盘失败（磁盘错误/权限）：不 reload、不广播，返回 500 { error }，配置文件保持原状
→ reloadRuntimeFlags() → appendEvent({ clientId: 发起页clientId, type: "runtime_flags_changed", data: { flags } })
   （flags 为 reload 后的**全量生效快照**，非 POST 子集——前端整体替换快照，防止其余键被清为 off；
    clientId 投递机制见 §4.4）
→ 返回与 GET 相同形态 + { envLocked }
```

- 写盘目标复用 `RUNTIME_FLAGS_FILE`（`server/运行开关.mjs:28-30`），测试可用 `OAW_RUNTIME_FLAGS_FILE` 指向临时文件，无需新机制。
- `.oaw/` 目录不存在时先创建。

### 4.4 事件（对抗审查 v2 修订）

`server/事件注册表.mjs` 登记一条：

```js
{ type: "runtime_flags_changed", lifecycle: true, persist: true, note: "运行开关热更（设置页保存后广播）",
  schema: { required: ["flags"], types: { flags: "object" } } }
```

- **persist 必须为 true**（初稿误设 false）：`server/事件存储.mjs:229` 对 persist:false 事件直接 `return null`，根本走不到 `:257` 的 `emitter.emit` 广播——persist:false 等于没有跨页通知。落盘代价可忽略（布尔快照小事件），回放亦无害。
- **跨标签页投递机制**：POST 路由携带发起请求页面的 clientId 调 `appendEvent`（`server/index.mjs:6266` 的 `memory_file_edited` 为完全同构先例：面板发起、`req.body.client` 传 clientId、persist 落盘、广播）。同 client 的其他标签页经全局事件流 `index.mjs:3748` 的 `event.clientId === clientId` 匹配收到（各标签页共享 localStorage clientId）；新开页面与其他浏览器上下文以 `/api/status` 全量拉取兜底。
- 事件进 `.oaw/events/事件流.jsonl`；非 Run 作用域，不设 runEvent。

### 4.5 前端快照与重渲染（`client/src/运行开关.js`）

```js
// 新增：事件驱动的快照替换 + 版本号订阅
let version = 0;
const listeners = new Set();
export function applyRuntimeFlagsSnapshot(next) { snapshot = next; version++; listeners.forEach(cb => cb(version)); }
export function useRuntimeFlagsVersion() { /* useState + useEffect 订阅 listeners */ }
```

- `App.jsx` 全局事件流处理 `runtime_flags_changed` → `applyRuntimeFlagsSnapshot(event.data.flags)`；顶层组件订阅 `useRuntimeFlagsVersion()` 触发重渲染，下游 `flag()` 内联读取（`App.jsx:852-854`、`3231-3236` 等约 40 处）自然生效。
- mount 期一次性接线两处（`ChatPanel.jsx:813` composerUnified、`ChatPanel.jsx:1200` interactionHub）改为同时订阅版本号重新 apply——这两处已有 `active + apply` 模式，改造量小。
- `/api/status` 首拉逻辑不变（`initRuntimeFlags`）。

### 4.6 设置页 UI（`client/src/components/SettingsPanel.jsx`）

- `SETTINGS_NAV`（`SettingsPanel.jsx:62-89`）新增分组：`{ id: "flags", label: "功能开关", items: [["flags", "功能开关", "toggle"]] }`。
- 新分区组件 `FlagsSection`：按 §5 白名单渲染常用组（默认展开）与高级组（折叠）；行 = 名称 + 说明 + 来源徽标 + Toggle。
- 来源徽标：`sources[key]` → 「默认」「配置文件」「环境变量」；env → Toggle disabled + 提示「环境变量接管，修改不生效」。
- 切换即 POST（无整页保存按钮）；护栏/族总开关关闭时 `askConfirm`；失败 `notifyError` 并回滚本地状态。
- api.js 新增 `runtimeFlagsGet`/`runtimeFlagsSave`（仿 `mapSettings`/`mapSettingsSave` 模式）。

**端到端判据（`scripts/开关设置端到端测试.mjs`，用户明确的重点要求）**：

基座复用 `scripts/聊天界面冒烟检查.mjs` 的 playwright chromium 接线（`聊天界面冒烟检查.mjs:38-50` 的 `loadChromium` 模式）；隔离与子进程拉起沿用 `scripts/恢复隔离测试.mjs:47-54` 的全套先例——`PORT:"0"` 随机端口、`OAW_RUNS_DIR`/`OAW_EVENT_DIR`/`OAW_INSTANCE_DIR`/`OAW_GOAL_DIR`/`OAW_WRITE_LOCK_DIR` 全部指向临时目录，加 `OAW_RUNTIME_FLAGS_FILE` 临时文件与临时工作区，服务地址以子进程输出等待就绪（`恢复隔离测试.mjs:93-102` 的 startServer 模式），**不触碰用户真实 `.oaw/` 与 3002 端口**。判据任一不满足即 FAIL、退出码 1：

1. **分区渲染**：打开设置面板 →「功能开关」分区出现；常用组展开、高级组折叠；**按组展开后分别计数**（分区为条件渲染 `SettingsPanel.jsx:777/790` 模式，折叠组行不在 DOM，不能整页数行）；行集合与 `editable` 白名单一致；`visualEffectsOff`/`runBudgetUnlimited` 行有反向语义标注。
2. **切换即生效（核心链路）**：切换 `creativeCanvas` → DOM 门控即时变化（产物页签「创作画布」按钮 disabled 状态翻转，`App.jsx:3231`）→ GET `/api/runtime-flags` 生效值翻转 → `runtime-flags.json` 落盘语义键正确。
3. **跨标签页同步**：同一 browser context 开两个标签页（共享 localStorage clientId），A 页切换 `creativeCanvas`（POST 携带 A 页 clientId，§4.4 投递机制），B 页**不刷新**收到 `runtime_flags_changed` 后门控 UI 同步翻转。
4. **env 接管锁定**：以 `OAW_CREATIVE_CANVAS=1`（与默认相同但来源为 env）重启实例 → 该行显示「环境变量接管」徽标、Toggle 不可点；通过 API 强发 POST 也不改变该键。
5. **restartRequired 徽标**：`dataAdapters` 行显示「重启后生效」徽标，切换允许、写盘生效但页面门控不变。
6. **护栏二次确认**：关闭 `teamGuard` → 先弹应用内确认框；取消 → 无 POST、无变化；确认 → POST 且生效。
7. **持久化与恢复**：刷新页面 → 快照与文件一致；**重启服务实例**（HTTP 层重新 spawn）→ 不带 env 时新实例按文件值生效（加载期求值点一并验证：`cadAgent` 关后 `/api/doc` 不再接受 dxf/dwg、能力白名单无 cad_edit）。
8. **坏路径**：POST 白名单外键 → 400 且快照不变；非布尔值 → 400；写盘失败以**跨平台手法**模拟——`OAW_RUNTIME_FLAGS_FILE` 指向一个**目录**路径（写入触发 EISDIR，Windows chmod 不阻断写入不可用）→ 500、快照不变、无事件。
9. **JSON 容错**：预置损坏的 `runtime-flags.json` 启动 → 服务正常起、全部回落默认值（对应 `运行开关.mjs:45-49` try/catch）。
10. **无错误边界**：整个流程无「组件出错，请刷新页面」、无 pageerror、无非噪声 console.error（对齐 ui-smoke 判据）。

## 8. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 运行中任务语义变化 | 分两类如实处理：**创建时快照项**（任务白名单、runBudget）当轮不变，热更测试显式断言；**逐次读取项**（如 `writingOneShot`，`task.mjs:323/715`）下轮调用即生效——交付说明注明「设置页切换对运行中任务的逐次读取项也即时生效」 |
| dataAdapters 热更不生效 | 白名单标注 restartRequired，UI 显示「重启后生效」；不承诺运行中卸载 |
| 白名单函数化破坏审批/能力契约 | 集合成员逐字不变，仅求值时机变化；`test:capability-contract` 守护 |
| 前端个别 mount 期缓存开关值 | 已知两处接线改造；其余在下一次导航/会话加载生效，交付说明如实注明 |

| env 优先级被绕过 | POST 对 env 接管键拒绝写盘；热更测试断言 |
| 热更引入回归 | 回滚 = revert 对应提交；`.oaw/runtime-flags.json` 手工清理后重启即回到基线 |
