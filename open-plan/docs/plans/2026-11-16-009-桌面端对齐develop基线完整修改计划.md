> 基线：`develop` @ `509182c7`（v0.13.25 + 7 个未推送提交，全部已验证）
> 上游决策：[ADR 0024 壳优先与平台适配层](../决策记录/0024-桌面端采用壳优先与平台适配层.md)、[022 工程结构与冲突治理](2026-11-06-022-桌面端工程结构、安装包收敛与双形态冲突治理.md)、[023 完整修改计划](2026-11-06-023-桌面端完整修改计划（0.13.x）.md)（文档状态未更新，主体已由 `23ed8a21`~`6949ed4e` 落地）

## 1. 目标

1. **固化基线**：把 develop 当前状态（含画布视频、预览视频、开始页/产物卡、会话流修复、008 止血）固化为桌面端 v0.13.26 的唯一基线；桌面端不新增业务功能，只做对齐、验证与打包。
2. **需求对齐**：把 023 计划遗留决策与本轮新功能逐条映射到桌面端行为，形成可验收清单。
3. **产物可用**：产出 NSIS 安装包 + 便携 ZIP 双形态，并通过产物冒烟。

## 2. 现状与差距

| 项 | 现状 | 差距 |

| 版本 | desktop/package.json = 0.13.25；根 = 0.13.25；develop 领先 origin 7 提交未发布 | **需 bump v0.13.26 并同步两处** |
| 随包二进制 | `desktop:prepare`（officecli / LibreDWG：DWG 读可用、写回另存 `-修改.dxf`） | 需重新执行并核对清单 |

## 6. 测试与验收口径

- `npm run desktop:test`：既有契约全绿 + 新增冒烟断言。
- `npm run desktop:dist / pack / zip / smoke` 全链路通过；体积漂移记录在案。
- `npm run verify`（web 形态）保持 exit 0。
- 手工验收（验收口径）：桌面端内画布视频可播、预览视频可播且进度条可拖、产物卡打开方式走系统应用、开始页入口可用、`OAW_DESKTOP=0` 回退正常。

## 7. 不做清单

- 不新增桌面端专属 UI 或业务功能（一份源码原则）。
- 不引入 ODA（DWG 写回维持另存 dxf 降级）。
- 不做自动更新（installer-update）机制，另行立项。
- 不动 server/client 业务代码；008 第二阶段单独实施。

## 8. 风险

- 打包环境依赖（NSIS/缓存配方）在受限环境的历史问题——沿用 `6ac8dc58` 配方并保留失败回退到 `--dir`。
- 视频素材体积使安装包变大（用户工作区数据不入包，随包仅 officecli/LibreDWG，理论不受影响）。
- Electron 33 的 Chromium 对 `video/mp4`（H.264）支持依赖系统编解码——冒烟 2.3 用 H.264 mp4 实测，必要时 webm 兜底验证。
