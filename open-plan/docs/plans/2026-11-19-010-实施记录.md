## 2. 关键实现决定（与对抗审查对齐）

1. **P2 两条路径**：`completed` 不在 `CONTINUABLE_RUN_STATUSES`，因此推进新开 Run（`createTaskEnvelope` + `beginRun` + `executeContinuation` 收尾链），恢复才用 `startContinuation`。审查 M1/R2。
2. **任何来源的 cancelled 都不推进**（用户取消/静默回收/取消看门狗），判定用持久字段语义而非内存态。审查 M3/R3。
3. **空闲判定全部复用既有轻量接口**：`agentManager.listSessionStates()`、`listPendingApprovals()`、`pendingAsk()`、`listRunSummaries({sessionId})`；禁止构造完整 Run 列表（1976ms 前车之鉴）。审查 M2/R1。
4. **P3 只做受支持的部分**：`session_before_compact` 的形状已从 SDK 类型实证（`CompactionPreparation` 提供 `messagesToSummarize/tokensBefore/firstKeptEntryId/fileOps`），所以诊断可行；**历史逐条改写不可行**（该钩子只能返回 `cancel` 或整段 `CompactionResult`，写私有 `state.messages` 违反"未实证不接线"）。
5. **P2 默认关的说明**：ADR 0043（同日）要求新开关默认开；本轮用户对 P2 明确拍板「默认关」，按 AGENTS.md §2 用户当轮指令优先，保留默认关，并在 `/api/status` 暴露三项便于设置页切换。

- **P3.1c（内存改写历史）**：用户拍板时选了「1b 先做 + 并行实证 1a」，且 Pi 无受支持的历史改写 API（仅能读私有 `session.agent.state.messages`），不做。
