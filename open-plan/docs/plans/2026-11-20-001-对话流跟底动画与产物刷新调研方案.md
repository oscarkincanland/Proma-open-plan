## 1. 逐项根因

### 1.1 跟底失效（问题 1）

机制现状：`followLatestRef`（跟随意图）+ `onScroll` 重算（ChatPanel.jsx:5126-5137）+ v3 每帧 pin（:5166-5175）+ 「回到底部」按钮重置跟随（:5138-5148）。

三个叠加根因：
1. **onWheel 一刀切**（仅 transcriptV3 开启时挂载）：`chat-body onWheel → followLatestRef.current = false; setShowScrollToBottom(true)`（:5577）。任何滚轮事件——包括「贴底时向下滚一把」「轻微误触」——立刻杀死跟随并弹按钮。流式期间内容持续增高，手一碰滚轮就掉出跟尾，只能反复点按钮。
2. **流式增高不重判**：token 追加只靠「用户上次滚动的意图」续跟（:5182-5183 注释明言不重判底部距离）——意图被误杀后没有自愈路径。
3. **DSH 意图控制器是死代码**：`会话流/滚动意图.js` 已按 [2026-11-14-001 对标方案](2026-11-14-001-会话流对标DSH完整方案.md) §阶段3 建好（createScrollIntent：手势中断/滚回恢复/程序滚动不退出/lock 冻结/restoreFollow），ChatPanel.jsx:42 已 import、:5105-5107 已创建 `scrollIntentRef`——**但全文件无一处调用**（grep `scrollIntentRef.current` 仅创建处）。对标方案阶段3 勾选完成（该文档 :233-235），但 `test:scroll-follow` 集成验收从未存在——实际的 `test:scroll-fold`（scripts/会话流滚动与折叠测试.mjs）只测了模块纯函数不依赖 DOM/React（:212-213），本次实跑 exit 0 全绿。**验收只测纯函数、集成层零断言，是"验收通过但线上一刀切"的结构原因。**

### 1.2 动画与跳动（问题 2）

现状动效清单（已落地）：打字机 90 字/秒 + 积压 0.24s 追赶（components/流式文本队列.js:6-14、会话流/useTypewriter.jsx）；工具行/工具卡插入前 flushTextReveal 防裂句（ChatPanel.jsx:2361-2392）；运行态 TextShimmer 扫光（TimelineRow.jsx:23,45、ChatPanel.jsx:9232、styles.css:12376）；折叠单帧钟（折叠驱动.js → RunFoldBar.jsx）；动效闸门 reduced-motion 落定（界面外观.js:176-208）。

跳动嫌疑（活人感差的具体来源）：
1. **阶段小结/工具行插入无入场过渡**——硬插即跳（行直接进列表）；
2. **流式气泡无最小高度预留**——空泡起步、首 token 后骤然撑高，视口内容上跳；
3. **打字机节奏恒定**——90 字/秒匀速+机械追赶，无标点停顿、无长短句节奏（活人感最大差距）；
4. 执行事件批量入列（appendExecutionEvent 裁剪 300 条）可能整块刷新插入。

约束（不可违反）：动效治理（test:motion）登记齐全、任意时刻活跃扫光 ≤1、reduced-motion/动效 off 全部落定、入场动画仅运行中的时间流播放且**历史回放不重播**（DESIGN.md:317）、动效时长消费既有令牌（DESIGN.md:500 禁止直写魔法值）。

### 1.3 更新记忆触发老式对话流（问题 3，假说按审查修正）

- 客户端执行流展示集合只含 memory_initialized / memory_proposal* / memory_written / memory_file_edited（事件展示.js:119-131）；**memory_extraction_*（执行句柄.mjs:360-391，Run 成功后异步发出）与 memory_recall_*（agent.mjs:8109-8130，带本轮 activeRunId）不在其中**。
- 抽取类事件带已完结 runId，被终态围栏丢弃（ChatPanel.jsx:2912）；即便不丢也无展示映射。记忆阶段在对话流内**要么不可见、要么落进非 v3 通道**——「老式对话流」的确切落点未定位。
- 无 runId 的消息与系统气泡走 **C7 旧块式渲染**（渲染通道清单 §1），记忆阶段插入的系统消息/气泡即呈现旧样式。
- 注：召回事件 runId 即本轮 Run id（agent.mjs:7271→7516→8110 时序），原「占锚抢占」假说降级为复现时待验证项。
- 实施第一步：受控复现「记忆更新时刻」的 DOM 形态（探针记录命中的渲染通道），再按通道清单 §4 归位到 C1/C2，不新增通道。

### 1.4 本轮产物不实时刷新（问题 4，审查修正后重写）

- 客户端刷新令牌只认 `run_finished / file_changed / artifact_published / artifact_staged(仅 flag 开)`（App.jsx:1634）——其中 **`artifact_staged` 在 flag 开时已在内**；
- **关键事实（审查发现）**：运行中 Run 的 artifacts 投影仅在 `RUNTIME_FLAGS.stagedVisible`（**默认关**）开启时由 touchedPaths 临时投影（runs.mjs:1914-1929）；flag 关（默认）时「artifacts 仅在 run 结束时由 finalizeFileChanges 装配」（runs.mjs:1916 注释原文）——**默认配置下运行中面板读到的是空列表，扩任何客户端事件清单都无效**；
- `artifact_created` 为幽灵事件（全仓库不存在，仅方案自引）；`artifacts_validated` 是收尾事件（runs.mjs:1566-1578，紧邻 run_finished），补进刷新清单增量价值≈0；
- 「本轮」投影按 **sessionId** 过滤（工作产物面板.jsx:99,158）——数据面无问题。
- **结论：问题 4 的修复方向必须先拍板**（见 §5 拍板点 2），纯前端修法在默认配置下无效。

## 2. Qoder/DSH 对标 vs 现状差异清单

| 对标项 | 现状 | 差距 |

## 3. 修复与增强方案

### P1.1 接通滚动意图控制器（修问题 1，对标收尾；**仅 transcriptV3 路径**）

1. `updateScrollFollowState`（v3 分支）改走 `scrollIntentRef.current.onScroll(metrics)`（基线 80px 分支保持现状——**flag 关时 scrollIntentRef 为 null，不得触碰**，审查②[高]）；
2. `onWheel` 改意图语义：仅 `deltaY < 0`（上滚意图）调 `interrupt()`；贴底向下滚不杀跟随；滚回 40px 灰度阈值内由 onScroll 自动恢复 following（模块已有）；
3. 「回到底部」按钮 / 发送消息 → `toBottom()`；程序滚动（跟底 pin、位置恢复、折叠补偿）期间 `lock()/unlock()`，**锁窗口须覆盖 unlock 后异步派发的首个 scroll 事件**（审查②）；
4. 切会话恢复位置 effect（ChatPanel.jsx:1108-1117）改用模块级 `restoreFollow(recordedTop)` 同步 intent，消除双事实源；
5. `followLatestRef` **保留为镜像**（intent 为唯一事实源，followLatestRef 同步维护）——既有 4 处写点与 2 处源码断言测试（AVA时间线测试.mjs:54、主任务流可信度测试.mjs:94）不被破坏；
6. 删除 :5577 的 onWheel 一刀切闭包（v3 分支内替换为意图语义 handler）。

### P1.2 记忆阶段渲染归位（修问题 3）

第一步受控复现（临时探针记录记忆更新时刻命中的渲染通道与 DOM，留痕实施记录）；确认落点后按渲染通道清单 §4 归位：目标是在 C1/C2 时间线内以行/阶段小结呈现记忆阶段（复用既有行，零新通道），杜绝无 runId 旧块式渲染与围栏丢弃造成的黑洞。若复现发现落点在服务端事件缺登记（事件展示.js 增补映射），按注册表规矩走事件展示层登记，不动事件注册表。

### P1.3 产物实时刷新（问题 4，**须先拍板方向**）

三选一（详见 §5 拍板点 2）：
- **A. flag 链路验证 + 文档化**：维持服务端现状；验证 `stagedVisible` 开启后「运行中产物可见 + artifact_staged 已在刷新清单」链路端到端可用，并在产物面板补一句「运行中产物可见性受 stagedVisible 开关控制」的空态文案；不动默认配置。
- **B. 服务端投影解耦 flag（动服务端）**：运行中 artifacts 投影不再受 stagedVisible 限制（或 flag 默认开）——超出当前不做清单，须用户明确拍板，且需评估演示数据/暂存噪音风险。
- **C. 本轮不做问题 4**：仅留档。
（默认推荐 A——先让用户知道开关存在，观察一段时间再决定是否走 B。）

### P2 活人感动效包（增强，拍板选做）

- **E1 节奏拟人**：打字机变速——短句慢速、长段提速（上限不变，防追赶失控）；标点微停顿（句号 90–140ms、逗号 40–60ms；积压超阈值自动关闭停顿，保证不被拖慢）。改动点：`计算展示字符数` 扩签名（**波及 3 个调用点**：ChatPanel.jsx:2336 rAF 循环、会话流投影.js:29 advanceTypewriter、components/会话流/useTypewriter.jsx:24，审查①[低]）+ 参数常量集中一处；reduced-motion/off 直接落定（复用既有闸门）。
- **E2 入场过渡与高度预留**：运行中新工具行/阶段小结行入场过渡消费 `--dur-fast` 令牌（不直写 120ms 魔法值），**仅运行中的时间流播放，历史回放/切会话/分页插入不重播**（DESIGN.md:317 硬约束）；流式气泡 min-height 预留一行，减少首 token 跳变；整轮折叠、分页、模式切换维持"动画禁区"（不加动效）。
